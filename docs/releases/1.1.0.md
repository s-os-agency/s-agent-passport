# S/Passport 1.1.0 — Passkeys and Zero Trust

Release candidate, 16 October 2026. Deployment and a real device ceremony remain to be verified.

S/Passport strengthens its existing passkey vault lock: the server now requires authenticator user verification, pins the relying-party origin to deployment configuration, and scopes the five-minute unlock to the authenticated browser session. An unavailable owner security policy blocks sensitive exports. Adding a second passkey, removing a credential, and changing the vault lock require fresh passkey verification. Logout clears the session's outstanding challenges and unlock.

Passkeys supplement the existing account login. They do not grant agent capabilities, establish device posture, or replace GatePass authorization. Synced passkeys are supported; enrollment does not attest that a device is managed.

## Upgrade

Set `PASSKEY_ORIGIN` to the exact public HTTPS origin (scheme, hostname, and optional port, with no path). Keep the existing hostname to preserve credential scope. Request and forwarded headers are not a source of production trust. There are no schema or dependency changes.

This release uses in-process challenge and unlock state. Run one application instance; multiple instances require a shared atomic TTL store before rollout. Restarts clear verification state.
